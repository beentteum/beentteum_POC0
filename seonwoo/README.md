# 0. Coding Test - Lv.0

## 가장 큰 수 찾기

### 문제 출처

- 프로그래머스 Lv.0
- 문제명: 가장 큰 수 찾기

### 문제 설명

정수 배열 `array`가 주어질 때, 배열에서 가장 큰 수와 그 수의 인덱스를 담은 배열을 반환한다.

### Requirements

- 정수 배열 `array`를 입력받는다.
- 배열에서 가장 큰 값을 찾는다.
- 가장 큰 값의 인덱스를 함께 찾는다.
- `[가장 큰 값, 인덱스]` 형태의 배열을 반환한다.

### 입력값

- `array`: 정수 배열

### 출력값

- 가장 큰 수와 해당 수의 인덱스를 담은 정수 배열

### 제한조건

- `1 ≤ array의 길이 ≤ 100`
- `0 ≤ array의 원소 ≤ 1000`
- `array`에 중복되는 숫자는 없다.

### 풀이 Flow

```text
정수 배열 입력
↓
첫 번째 값을 초기 최댓값으로 설정
↓
배열을 순서대로 탐색
↓
현재 값이 기존 최댓값보다 큰지 비교
↓
더 크다면 최댓값과 인덱스 갱신
↓
[최댓값, 인덱스] 반환
```

### Business Logic

1. 배열의 첫 번째 원소를 초기 최댓값으로 설정한다.
2. 최댓값의 초기 인덱스를 `0`으로 설정한다.
3. 두 번째 원소부터 배열의 마지막 원소까지 순회한다.
4. 현재 원소가 저장된 최댓값보다 큰 경우 최댓값을 갱신한다.
5. 해당 원소의 인덱스도 함께 저장한다.
6. 배열 탐색이 끝나면 최댓값과 해당 인덱스를 반환한다.

### Code

```java
class Solution {
    public int[] solution(int[] array) {

        int max = array[0];
        int maxIndex = 0;

        for (int i = 1; i < array.length; i++) {
            if (array[i] > max) {
                max = array[i];
                maxIndex = i;
            }
        }

        return new int[]{max, maxIndex};
    }
}
```

### Test Case

```text
입력: [1, 8, 3]
출력: [8, 1]

입력: [9, 10, 11, 8]
출력: [11, 2]
```

프로그래머스 테스트 케이스 2개를 실행하여 모두 통과한 것을 확인하였다.

### 핵심 포인트

배열을 순회하면서 현재 값과 기존 최댓값을 비교하고, 조건을 만족하는 최적의 값을 선택하는 기본적인 비교 로직을 이해하였다.

### PoC 기능과의 연결

「가장 큰 수 찾기」는 여러 값 중 가장 큰 값을 비교하여 선택하는 문제이다.

빈틈의 목적·조건 기반 카페 추천 기능도 각 카페의 공간 조건을 기준으로 추천 점수를 계산한 뒤, 점수를 비교하여 더 적합한 카페를 우선 추천한다.

따라서 여러 후보의 값을 비교하고 가장 적합한 후보를 선택한다는 핵심 사고방식이 유사하다.

# 1. PoC 기능 개발

## 목적·조건 기반 카페 추천

### 1. Requirements

사용자가 방문 목적과 필요한 공간 조건을 선택하면,
시스템은 카페별 공간 정보를 기준으로 적합도를 계산하고 추천 결과를 제공한다.

#### 요구사항

- 사용자는 방문 목적을 하나만 선택할 수 있다.
- 방문 목적은 `공부 / 업무 / 대화 / 휴식` 중 하나이다.
- 사용자는 필요한 공간 조건을 선택할 수 있다.
- 추천은 AI가 아닌 Rule-based 방식으로 처리한다.
- 시스템은 방문 목적과 공간 조건을 기준으로 카페별 추천 점수를 계산한다.
- 시스템은 추천 점수가 높은 카페부터 추천 순위를 제공한다.
- 추천 결과에는 추천 근거를 함께 제공한다.
- 허용되지 않은 방문 목적이 입력되면 추천을 수행하지 않는다.
- 일부 조건을 만족하지 않는 카페도 추천 결과에서 제외하지 않고 추천 우선순위를 낮춘다.

#### 입력값

- `purpose`: 방문 목적
    - `STUDY`
    - `WORK`
    - `TALK`
    - `REST`
- `needOutlet`: 콘센트 필요 여부
- `needWifi`: 와이파이 필요 여부
- `preferredNoise`: 선호 소음 수준
    - `LOW`
    - `MEDIUM`
    - `HIGH`

#### 출력값

추천 카페 목록을 반환한다.

각 추천 결과에는 다음 정보를 포함한다.

- 카페 이름
- 추천 점수
- 추천 근거

### 2. User Flow

```text
사용자가 카페 추천 기능 진입
↓
방문 목적 1개 선택
↓
필요한 공간 조건 선택
↓
추천 요청
↓
입력값 검증
↓
목적이 허용된 값인가?
├─ 아니오 → 추천 실패
└─ 예
    ↓
더미 카페 목록 조회
↓
카페별 목적 적합도 계산
↓
사용자가 선택한 조건과 비교
↓
조건 만족 시 가점 / 불일치 시 감점
↓
추천 점수가 높은 순서로 정렬
↓
추천 순위와 추천 근거 반환
```

#### Exception

- 추천 요청 정보가 없음 → 추천 실패
- 방문 목적 누락 → 추천 실패
- 허용되지 않은 방문 목적 → 추천 실패
- 일부 조건 불충족 → 해당 카페를 제외하지 않고 추천 점수를 낮춰 우선순위 조정

---

### 3. Business Logic

1. 사용자의 방문 목적과 공간 조건을 입력받는다.
2. 추천 요청 정보가 존재하는지 확인한다.
3. 방문 목적이 `STUDY / WORK / TALK / REST` 중 하나인지 확인한다.
4. 방문 목적이 없거나 유효하지 않으면 추천을 중단하고 오류를 반환한다.
5. 준비된 더미 카페 목록을 조회한다.
6. 각 카페의 콘센트, 와이파이, 소음 정보를 확인한다.
7. 방문 목적에 따라 카페별 기본 추천 점수를 계산한다.
8. 사용자가 추가로 선택한 공간 조건과 카페 정보를 비교한다.
9. 선택 조건을 만족하면 점수를 추가하고, 만족하지 않으면 점수를 감점한다.
10. 일부 조건을 만족하지 않는 카페도 추천 후보에서 제거하지 않는다.
11. 추천 점수를 기준으로 카페를 내림차순 정렬한다.
12. 조건을 만족한 항목을 기반으로 추천 근거를 생성한다.
13. 정렬된 추천 카페 목록을 반환한다.

### 로직 요약

```text
목적 + 조건 입력
↓
입력값 검증
↓
더미 카페 목록 조회
↓
목적별 기본 점수 계산
↓
사용자 선택 조건과 비교
↓
조건 만족 → 가점
조건 불일치 → 감점
↓
모든 카페를 추천 후보에 유지
↓
점수 내림차순 정렬
↓
추천 근거 생성
↓
추천 결과 반환
```

### 4. PoC 구현 기준

본 PoC는 목적·조건 기반 카페 추천 기능의 동작을 검증하기 위한 최소 구현이다.

PRD/SRS에서는 목적 기반 추천을 Rule-based 방식으로 정의하고 있으나,
목적별 세부 점수와 가중치 수치는 고정되어 있지 않다.

따라서 본 PoC에서는 Rule-based 추천의 동작을 확인하기 위해 다음과 같은 점수 기준을 별도로 정의하였다.

#### 목적별 기본 점수

| 방문 목적 | PoC 추천 기준 |
|---|---|
| STUDY | 조용한 환경 +2, 콘센트 +1, Wi-Fi +1 |
| WORK | 콘센트 +2, Wi-Fi +2 |
| TALK | 보통 소음 수준 +2 |
| REST | 조용한 환경 +2 |

#### 사용자 선택 조건 점수

사용자가 직접 선택한 조건에 대해서는 다음 기준을 적용한다.

- 콘센트 조건 만족: +1
- Wi-Fi 조건 만족: +1
- 선호 소음 수준 만족: +1
- 사용자가 선택한 조건 불일치: -1

사용자가 선택한 조건을 일부 만족하지 못하는 카페도 추천 후보에서 제외하지 않는다.

대신 조건 불일치에 따라 추천 점수를 낮추고,
최종 점수를 기준으로 추천 우선순위를 조정한다.

※ 위 목적별 점수와 조건 불일치 시 `-1`점은 PRD/SRS에 정의된 공식 수치가 아니라,
본 PoC에서 Rule-based 추천 우선순위 계산 동작을 검증하기 위해 정의한 구현 기준이다.

#### PoC 구현 범위

본 PoC는 SRS의 목적 기반 추천 기능 중
**방문 목적과 공간 조건을 이용한 Rule-based 추천 우선순위 계산**을 검증하는 범위로 한정한다.

현재 구현에서는 다음 공간 정보를 사용한다.

- 콘센트
- Wi-Fi
- 소음 수준

실제 SRS에서 추천에 함께 활용하도록 정의된 좌석 정보, 거리,
현재·예상 혼잡도 등의 정보 연동은 이번 PoC 구현 범위에서 제외한다.

### 5. API

#### Endpoint

```text
POST /api/recommendations
```

#### Request Example

```json
{
  "purpose": "STUDY",
  "needOutlet": true,
  "needWifi": true,
  "preferredNoise": "LOW"
}
```

#### Response Example

```json
[
  {
    "cafeName": "빈틈 카페",
    "score": 7,
    "reasons": [
      "조용한 환경",
      "콘센트 사용 가능",
      "와이파이 사용 가능",
      "요청한 콘센트 조건 충족",
      "요청한 와이파이 조건 충족",
      "선호 소음 수준 일치"
    ]
  }
]
```

추천 결과는 추천 점수가 높은 순서대로 반환한다.

일부 조건을 충족하지 않는 카페도 결과 목록에 포함되며,
조건 불일치에 따른 감점으로 추천 순위가 낮아진다.

### 6. Exception

#### 방문 목적 누락

방문 목적이 입력되지 않은 경우 추천을 수행하지 않는다.

##### Request

```json
{
  "purpose": null,
  "needOutlet": true,
  "needWifi": true,
  "preferredNoise": "LOW"
}
```

##### Result

```json
{
  "message": "방문 목적을 선택해야 합니다."
}
```

HTTP Status:

```text
400 Bad Request
```
